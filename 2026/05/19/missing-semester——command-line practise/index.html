参数与 Globs

你可能见过像 cmd --flag -- --notaflag 这样的命令。这里的 -- 是一个特殊参数，它告诉程序后面不要再继续解析选项（flag）了。也就是说，– 后面的所有内容都会被当作位置参数（positional argument）。这有什么用？试着运行 touch -- -myfile，然后在不使用 – 的情况下把它删掉。

  • – 的作用：
    强制终止选项解析，后面所有内容都被当作普通的位置参数（文件名）

运行 touch -- -myfile ,创建了 -myfile 文件：

用命令 rm ./-myfile 删除文件

  • 为什么不能直接 rm -myfile？
    因为 rm 会把 -m 当成自己的选项（-m 是 rm 的一个参数），而不是文件名的一部分
  • 用 ./-myfile 的原理：
    加上相对路径前缀 ./ 后，整个字符串变成了一个路径，rm 就不会再把开头的 - 解析为选项了

进程替换 <(command) 可以让你把一个命令的输出当成文件来用。试着配合 diff 和进程替换，比较 printenv 与 export 的输出。它们为什么不一样？（提示：可以试试 diff <(printenv | sort) <(export | sort)）

先尝试命令 diff <(printenv | sort) <(export | sort)） ,看到（节选）：

不同点:

  • 输出格式不同:
    printenv：纯环境变量输出，格式为 VAR=value
    export：Shell 内置命令，输出格式为 declare -x VAR="value"（带引号和 declare -x 前缀）
  • 内容范围不同
    printenv：只打印环境变量（也就是被导出到子进程的变量）
    export：打印所有被标记为导出的变量 + 被导出的 Shell 函数
    如果 Shell 里定义了导出的函数（比如export -f myfunc），export会显示这些函数，而printenv完全不会显示
  • 特殊变量差异
    有些变量是 Shell 内部的，没有被导出，printenv 不会显示
    export 会显示所有被 export 命令标记过的内容，包括变量和函数

用脚本：

用命令 source marco.sh 加载函数到当前 Shell

  • 原理
    source 命令会把脚本里的函数、变量，直接加载到当前正在用的 Shell 里，而不是开一个新的 Shell 执行脚本，这样函数才能在当前终端直接用。

脚本解释：

  • MARCO_SAVED_DIR="": 这是一个全局 Shell 变量，在函数外面定义，所以 marco 和 polo 两个函数都能访问、修改它。专门用来存执行 marco 时的当前目录路径。
  • if [ -z "$MARCO_SAVED_DIR" ]：-z 是 Shell 测试符，判断变量是否为空。防止没执行 marco 就直接跑 polo，导致报错。
  • if [ ! -d "$MARCO_SAVED_DIR" ]：-d 是判断路径是否是一个存在的目录。防止你保存目录之后，把目录删了，导致 cd 失败。

信号与任务控制

在终端里启动一个 sleep 10000 任务，用 Ctrl-Z 把它挂起，再用 bg 让它继续在后台运行。然后使用 pgrep 找到它的 pid，再用 pkill 把它杀掉，整个过程都不要手动输入这个 pid。（提示：试试 -af 参数）

用命令 pgrep -af "sleep 10000" 找到pid，用 pkill -f "sleep 10000" 来杀掉：

原理：

命令 / 操作 核心作用
Ctrl+Z 向前台进程发送SIGTSTP信号，暂停进程，将其转入挂起状态
bg [任务号] 将挂起的任务转入后台继续运行，等价于发送SIGCONT信号恢复进程
pgrep -af "命令" 按完整命令行匹配查找进程，返回 PID，避免手动输入 PID
pkill -f "命令" 按完整命令行匹配杀死进程，全程无需手动输入 PID

假设你不想在某个进程完成之前启动另一个进程，你会怎么做？在这个练习里，限制条件始终是 sleep 60 &。一种实现方式是使用 wait 命令。试着启动这个 sleep，然后让一个 ls 等到后台进程结束后再执行。

不过，如果我们是在另一个 bash 会话里启动的，这个策略就失效了，因为 wait 只对当前 shell 的子进程有效。讲义里还没提到的一点是：kill 命令成功时退出状态为 0，失败时则非 0。kill -0 不会真的发送信号，但如果进程不存在，它会返回非 0。写一个叫 pidwait 的 bash 函数，接收一个 pid，并一直等待到该进程结束。你应该用 sleep 来避免空转浪费 CPU。

用命令 wait $! && ls :

  • $!：Shell 特殊变量，代表上一个后台进程的 PID
  • wait $!：等待 PID 为 $! 的进程执行完成
  • &&：只有前面的 wait 执行成功（进程结束），才会执行后面的 ls。执行后，终端会卡住 60 秒，等 sleep 60 结束后，才会执行 ls 列出文件。

文件与权限

（进阶）写一个命令或脚本，递归找出某个目录中最近修改过的文件。更一般一点，你能不能按“最近修改时间”列出所有文件？

用脚本：

  • find "$TARGET_DIR" -type f：递归查找目录里所有文件（不包含文件夹）
  • -printf "%T@ %Tc %p\n"：
    • %T@ → 修改时间（时间戳，用来排序）
    • %Tc → 人类能看懂的时间格式
    • %p → 文件路径
  • | sort -nr
    • sort -n → 按数字排序
    • sort -r → 倒序（最新的在最上面）
  • while read -r timestamp time_str file_path:
    • 一行一行读取结果，分成 3 个变量：时间戳、时间字符串、文件路径
  • head -n 1：只要排序后的第一行（最新的文件）
