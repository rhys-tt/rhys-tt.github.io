HTTP与浏览器解析

浏览器解析过程

  • TCP报文 → HTTP协议解析 → 读请求 → 返回响应报 → 包括 HTML、CSS、JS

页面类型

  • 静态页面
  • 动态页面 → 查询数据库

报文

  • 状态行：显示状态码(200 OK, 404 Not Found)
  • 响应头：显示content-type Content-Length
  • 响应体：实际内容

状态码分类

$2xx$ 成功 $3xx$ 重定向 $4xx$ 客户端错误 $5xx$ 服务器错误
200请求成功 301永久 400 格式 500 内部错误
201资源创建成功 302 临时 401 未授权 502网关代理无效响应
209 成功但无内容返回 304未修改 404 不存在 503 不可用
504 超时

会话技术

HTTP无状态性

  • 每次请求响应独立

  • 会话指在用户与网站或与Web应用之间建立持久连接
    ↓

  • 有唯一标识符：cookie/URL参数

会话技术

  • 客户端会话技术(cookie机制)
  • 服务端会话技术(session机制)

Cookie 机制

基本格式:<name>=<value>[;Expires =<data>][;Domain =<domain_name>][;path=<path>][; secure][;HttpOnly]

  • name：Cookie 名字，自定义
  • value：Cookie 存的值
  • ;Expires=<date>：设置 Cookie 过期时间。默认是会话 Cookie，浏览器关闭就自动删除。
    写了就是持久化 Cookie，到指定时间才失效。
  • ;Domain=<domain_name>：指定 Cookie 归属哪个域名
  • ;path=<path>：指定 Cookie 在哪个路径下生效
  • ;secure：标记安全属性

销毁

  • 定期删除,persistant cookie 写入磁盘
  • 浏览器关闭时被銷毀 ,Session Cookie 存在内存(较安全)
  • 手动销毁

问题

  • 大小&数量
  • 隐私
  • 安全

Session 机制

  • 一般以键值对形式存储,以PHP为例 sess_<sessionid>

工作流程:访问网站 → 发HTTP请求 → 检测无Session记录 → 创一个新Session并存服务器 → Set-cookie发送给用户浏览器 → 后续请求会自带Cookie并发服务器 → 接受请求,若session有效 → 恢复之前状态

局限性

  • 生命周期
  • 扩展性问题
  • 资源消耗

Web应用工作原理

HTTP请求

  • DNS解析域名为IP地址 → TCP连接 → 发送HTTP请求到服务器 → 服务器处理 → 数据库处理 → 返回响应 → 页面渲染

URL (Uniform Resource Locators,统一资源定位符)

  • scheme://[username: password@]hostname[:port]/path[?query][#fragment]
  • 协议 | 用户名 | 密码 | 主机名 | 端口 | 路径 | 查询参数 | 片段标识

DNS解析

  • 存在多级缓存
  • 从远近排序: 浏览器 > 系统 > 路由器 > IP服务器 > 根域名服务器 > 顶级域名服务器 > 主域名服务器
  • 作用:将人类可读域名转换为机器可读IP地址

TCP连接

  • HTTP协议使用时使用TCP协议作为其输层协议,会发起三次握手建立可靠的TCP连接:
    1. SYN：客户应端发送同步序列号 (SYN=1)到服务器。
    2. SYN-ACK：服务器确认并回复自己的序列号 (SYN=1，ACK=1)
    3. ACK：客户端确认服务器的序列号 (ACK=1)

RCE 远程命令执行

Linux命令常见分隔符

  • ; ：cmdl; cmd2 从左到右依次执行命令
  • &：cmd1&cmd2 将cmd1置于后台,立即执行cmd2
  • &&：cmd1&&cmd2 先执行cmd1,若成功,则执行cmd2
  • |： cmd1|cmd2 将cmd1输出作为cmd2输入
  • ||：cmd1||cmd2 先执行cmd1,若cmd1错误,才会执行cmd2.

防御
1. 禁用高危函数
2. 采用黑名单策略过滤关键字符
3. 采用escapeshellarg()(更安全)和escapeshellcmd()函数对特殊字符进行转义
4. 对输入格式进行合法性判断

包含敏感文件

  1. Linux系统

    文件 说明

PHP伪协议

  • file:// 访问本地文件
  • http:// 访问网址
  • ftp:// 用Ftp协议远程访问远程文件
  • php://filter 读取文件

    • read=<应用于读取链的过滤器列表>
    • write=<应用于写入链的过滤器列表>

  • php://input 执行代码
    • 只读流,访问HTTP请求原始数据 → 读取Body数据
    • 要求:
      • (1)配置项:"allow_url_include = On"
      • (2) Content-Type不能为”multipart/form-data” 类型
  • data:// 伪协议
    • 在脚本中访问数据流,适用于直接处理数据
    • 要求：
      • (1) PHP版本>=5.2
      • (2)配置项 allow_url_fopen = On
      • (3)配置项 "allow_url_include = On
    • 两种方式:
      • data://text/plain,<字符串>
      • data://text/plain;base64,<Base64编码后字符串

Php 特性

弱比较与强比较

  • $==$ 先将转换为字符串类型再进行比较
  • $===$ 先判断两种字符串类型是否相等,再比较

*自动转换规则

  • 例：$3e3=3\times10^{3}=3000$ 先将字符串解析为数字,例:3e3>900 → true
    *缺陷函数
  • 一、md5()获取不到数组的值,将返回NULL
  • 二、hash()无法处理数组类型,将返回NULL
    例:
  • nash (array('1' ) ) == hash (array('2')))
  • md5(array('1')) == md5(array('2'))
  • 三、strcmp(): 比较字符串,但当接受数组对比时,会返回Null(0)
  • 四、is-numberic: 检测是否为数字或数字字符串，当 404a 与404比较时,会将 404a 转换成 int 型，结果是相等

    8. 检查代码拼接方式

命令执行

  • 原理:调用system(),exex(),shell_exec()等系统命令执行函数,没有严格过滤和验证,导致可构造特殊输入,注入并执行任意系统命令
  • 危害:
    1. 完全控制服务器
    2. 数据泄露与破坏
    3. 植入后门程序
    4. 内网横向渗透
  • 审计方法:
    1. 定位危险函数
    2. 检查参数可控性
    3. 检查过滤与转义逻辑
    4. 检查命令拼接方式

文件读取

  • 程序在使用file_get_contents(), fopen(), readfile()等文件操作函数时,未对用户输入处理,则可构造特殊路径读取服务器任意文件
  • 危害:
    1. 敏感信息泄露
    2. 进一步攻击
    3. 代码审计
  • 审计方法:
    1. 定位文件操作函数
    2. 检查路径可控性
    3. 检查过滤与验证逻辑
    4. 检查文件类型

PHP框架漏洞

  • 定义:为简化Web开发而设计的基础架构,提供了一套通用的代码库和开发规范
  • 优势:提高开发效率,保证代码质量,增强可维护性, 提供安全基础

主流框架

  • ThinkPHP:国内主流车轻量框架,中文生态完善, MVC架构、TP5.X/6.x漏洞开发,二次开发易引发SQL注入,文件操作漏洞
  • Laravel:国际主流全功能框架,遵循PSR规范,漏洞集中 ORM查询,中件配置不当
  • Yil:高性能框架,适配高并发场景,多源于路由过滤, 参数验证缺失
  • Codelgniter:轻量极简框架,无强规范约束,易出命令/代码执行漏洞

thinkPHP 原生框架漏洞

  • 例:ThinkPHP5.x RCE:由于控制器名处理不当,导致攻击者可构造特殊控制器名绕过过滤,最终执行任意代码
  • 危害和修复:升级安全片版本,或安装官方提供补丁
  • 二次开发漏洞: SQL注入,XSS,文件上传,权限控制不当

目录结构解析

  1. public/(入口目录):包含index.php应用入口及静态资源,所有请求均由此进入
  2. application/(应用模块):存放业务代码。包含controller, model,view,及各类配置文件(config.php, database.php)
  3. thinkphp/(框架核心):框架底层实现,包含library核心类库和start.php启动文件
  4. vendor/(依赖包): Composer下载第三方库目录
  • 关键文件:除入口文件外 application/index/controller/index.php是默认的首页控制器,是业务逻辑的起点

Web安全代码审计

  • Seay源代码审计系统
  • 手工审计思路一危险函数追踪法,用户输入追踪法，逻辑漏洞
  • SQL:
    1. 找数据库操作函数
    2. 追踪用户可控参数
    3. 检查参数过滤逻辑
    4. 验证漏洞真实存在
